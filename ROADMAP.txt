PHASE 1 - MAKE IT REAL (the product is missing)            [3-4 days]
===============================================================================
Goal: a logged-in user can do something. Right now login leads nowhere
and there is no way to create a booking at all.

  [ ] 1. Fix config.js API_BASE (5 min)                             [m]
         Change: window.API_BASE = 'http://localhost:5000'
         To:     window.API_BASE = '';    // same-origin
         WHY: every login/signup/admin/reset call breaks on any real
         domain. Test by opening the site on a non-localhost host.

  [ ] 2. Server-side AI proxy (2-3 h)                               [h]
         a. Add to .env:  GEMINI_API_KEY=...
         b. Add to .env.example (commented, no real key)
         c. New route in backend/app.py:
              POST /api/ai-guide   { "kind": "destination"|"trip",
                                     "query": "..." }
            - reuse the two prompt strings currently in index.html
              and map.html
            - call Gemini with the key from os.environ
            - @rate_limit(max_requests=15, window=60)
            - return { "text": "..." }
         d. Replace the browser fetch in index.html:363 and
            map.html:296 with a fetch to /api/ai-guide
         e. Delete window.GEMINI_API_KEY from config.js
         WHY: a key in the browser is stolen and billed within days.

  [ ] 3. User auth guard + /api/me (1-2 h)                          [h]
         a. @require_user decorator (like require_admin but checks
            any valid token from the Authorization: Bearer header)
         b. GET /api/me -> { id, name, email, contact }
         c. Read the token from localStorage 'manzilToken'
            (login.html:172, createaccount.html:389)
         d. sendToken() helper in a shared auth.js
         WHY: manzilToken is stored today but NEVER sent anywhere -
         login currently does nothing for users.

  [ ] 4. Booking API (half a day)                                   [d/2]
         a. POST /api/bookings  (@require_user)
            fields: booking_type, source, destination, travel_date,
                    amount  -> validate all, travel_date as ISO date
         b. GET  /api/bookings/mine (@require_user)
         c. DELETE /api/bookings/<id> (@require_user, owner only)
         d. Change schema: travel_date VARCHAR(20) -> DATE
            (update schema.sql fresh-create AND add a commented
            ALTER for the existing live DB, same style as before)
         WHY: tables + admin UI exist but NOTHING can create a row.

  [ ] 5. "My Trips" page (1 day)                                    [d]
         - New mytrips.html: list of the user's bookings, status,
           total spent, cancel button, "Plan a trip" CTA -> index.html
         - Add link in the header/footer of every page
         - Show a "Hi, <name>" state when logged in (uses /api/me),
           "Login" when not
         - Redirect to index.html if no token
         WHY: gives login a purpose; this is the page judges will look
         for after the demo of signing up.

  [ ] 6. Newsletter + contact endpoints (1-2 h)                     [h]
         a. Table: subscribers(email UNIQUE, created_at)
            Table: messages(id, name, email, subject, body, created_at)
         b. POST /api/newsletter  (validate email, dedupe, 409/200)
         c. POST /api/contact     (validate, store)
         d. Wire index.html newsletter form (currently a fake
            "Subscribed!" button) and contact.html form
         e. Show messages in the admin panel (new tab - the tab
            infrastructure already exists in admin.html)

  [ ] 7. Password change for logged-in users (1 h)                  [h]
         PUT /api/me/password  (current + new, bcrypt check)
         WHY: DPDP + basic hygiene; reset email alone is not enough.

  DONE WHEN: fresh browser -> sign up -> plan -> book -> see it in
  My Trips -> cancel it. All with the network tab open and no errors.

PHASE 2 - MAKE IT SHIP (free deployment)                    [2-3 days]
===============================================================================
Goal: a live URL you can put in the SIH submission.

  [ ] 1. Production server (2-3 h)                                  [h]
         a. Add gunicorn to backend/requirements.txt
         b. Add Procfile or start-prod.sh:
              gunicorn -w 2 -b 0.0.0.0:$PORT backend.app:app
         c. Dockerfile (optional but nice for judges)
         NOTE: with 2 workers the in-memory rate limiter and reset
         tokens break - see step 3 FIRST if you skip the DB move.

  [ ] 2. Move in-memory state into Postgres (2-3 h)                 [h]
         a. Table rate_limits(key TEXT, hits INT[], ...) or simply
            (key, timestamp) rows, pruned on write
         b. Table reset_tokens(token_hash PRIMARY KEY, email, exp,
            used_at) - store only the HASH of the token
         c. Replace rate_limit_store and used_reset_tokens dicts
         WHY: today a restart or a 2nd worker silently disables rate
         limits and allows reset token reuse.

  [ ] 3. Free hosting + DB (half a day)                             [d/2]
         - Host:  Render / Railway / Fly.io free tier (Flask, free)
         - DB:    Neon / Supabase / Aiven free tier (Postgres, free)
         - Apply schema.sql, then seed.sql on the hosted DB
         - Set all env vars in the host's dashboard (never upload .env)
         - Set API_BASE = '' (Phase 1 step 1) so it works on the host

  [ ] 4. Static asset performance (1 h)                             [h]
         a. Compress homebackground.png (2.4 MB -> target <200 KB):
            pngquant / cwebp / tinywebp, all free
         b. Compress ankit.jpeg (620 KB), sonu.jpeg, sanya.jpeg
         c. loading="lazy" on team photos and below-the-fold images
         d. Verify size: du -h *.png *.jpeg after

  [ ] 5. Cache + compression headers (1 h)                          [h]
         - after_request: Cache-Control: public, max-age=604800 for
           static assets (keep no-store for /api/*)
         - gzip via the host or Flask middleware (flask-compress,
           free)

  [ ] 6. OG + meta tags (1-2 h)                                     [h]
         - <meta name="description"> on all 17 pages
         - og:title, og:description, og:image, og:url, twitter:card
         - use icon.png / a cropped hero as og:image (<=1 MB)
         WHY: WhatsApp/X previews are your viral loop; 15 pages
         currently share as plain text.

  DONE WHEN: https://your-app.on-render.com loads in <3s on mobile
  throttling, and sign up + booking works on that URL.

PHASE 4 - DEMO THE PITCH (free data instead of paid APIs)   [2-3 days]
===============================================================================
Goal: cover the SIH problem statement (itinerary, budget, hotels,
transport) without paying for a single travel API.

  [ ] 1. Day-wise itinerary (1-1 d)                                 [d]
         - Extend POST /api/ai-guide with kind='itinerary':
           { destination, days, budget, interests }
         - Prompt Gemini for JSON:
           { days: [ { day, morning, afternoon, evening, cost } ] }
         - Parse + validate server-side, cache the result in a table
           itinerary_cache(query_hash, payload, created_at)
         - Render as day cards on map.html / a new trip.html

  [ ] 2. Budget estimate (2-3 h)                                    [h]
         - From the same itinerary JSON: sum cost per day
         - Breakdown: stay / transport / food / activities
         - Static price table in JSON (free, editable): a small
           city->cost-per-day dataset for your 5 demo cities

  [ ] 3. Demo city data instead of paid APIs (half a day)           [d/2]
         - data/<city>.json: 5-8 hotels, 5 things to do, 3 eateries
           (hand-written, real places - judge-checkable)
         - Serve with GET /api/places?city=...
         - BE HONEST in the pitch: "integration layer ready,
           provider keys pending - here is the contract"

  [ ] 4. Transport cards (2-3 h)                                    [h]
         - Use the free Overpass API (OpenStreetMap) for nearby
           stations, or reuse the same static JSON approach
         - Show metro/rail/airport info for the chosen destination

  [ ] 5. Replace rss2json.com blog (2-3 h)                          [h]
         - 3-5 real posts as HTML/Markdown, served by Flask or
           static files, listed on blog.html
         - Free, no third party that can vanish mid-judging

  [ ] 6. Save itineraries (2 h)                                     [h]
         - Table saved_trips(user_id, title, payload, created_at)
         - POST/GET /api/me/trips, show on My Trips page
         - THIS is what makes it "personalized" per the PS

  [ ] 7. Nominatim/Photon hygiene (1 h)                             [h]
         - Send a real User-Agent with contact info (policy)
         - Cache results in a small table to cut repeat calls
         - Policy: https://operations.osmfoundation.org/policies/nominatim/

  DONE WHEN: pick a city -> get an itinerary + budget + places ->
save it -> see it under My Trips. Fully offline-capable data.
